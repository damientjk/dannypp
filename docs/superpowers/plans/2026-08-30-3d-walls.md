# 3D Room Walls Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the flat, synthetically-shaded wall tile every room currently uses with a real, per-theme 2-row wall (a "cap" row + a "base" row) cropped from the asset pack's dedicated wall sheet, so walls read as having actual height instead of a flat painted band.

**Architecture:** Every room's back wall (the wall opposite its door, where the window already lives) grows a second tile row that sits just outside the room's existing footprint. The room's interior size, desk positions, and decor are untouched -- only the map's overall canvas grows by 2 tile rows (1 for each room row's cap) to make room for it. Each of the 6 rooms gets its own 2-row wall texture (cap + base) plus 2 window-composited variants of the base row, picked to match its floor theme, replacing the single global wall texture + hand-coded gradient hack every room currently shares.

**Tech Stack:** Python (PIL) asset-generation scripts, no runtime/engine code changes -- `TiledMapRenderer.ts` reads tile dimensions from `map.json` directly and has no hardcoded map size.

**Spec:** No separate spec doc. This is a bounded follow-on to `docs/superpowers/specs/2026-08-29-room-theming-design.md`, scoped and approved in-chat on 2026-08-30 (short design presented, user chose the two-row/real-depth option over a texture-only swap).

## Global Constraints

* Room interior size, desk positions, decor positions, and collision behavior for existing interior tiles must not change -- only wall rendering and overall canvas height change.
* No engine/runtime TypeScript changes -- confirmed `TiledMapRenderer.ts`, `WorldCanvas.tsx`, `agentSim.ts` have no hardcoded map width/height; they read `map.json` at runtime. If a task discovers otherwise, stop and flag it -- that would be new information contradicting this constraint.
* `generate-world-map.py`, `generate-world-tileset.py`, and `generate-room-decor.py` must stay in sync on room geometry and GID numbering by importing shared values/functions from `room_layout.py` -- never hardcode the same number in two files (existing repo convention, see room_layout.py's own docstring).
* All 3 generator scripts are run via `py <script>.py` (not `python3` -- broken stub on this machine) from `apps/web/scripts/`.
* No pytest/test framework exists for these Python scripts -- verification is: script runs without an `AssertionError`, the regenerated `map.json`/`tileset.png` look correct on visual inspection, and the existing Vitest suite (`npm run test -w @launchpad/web`) still passes (it uses self-contained mock map fixtures, not the real generated files, so it is not expected to need edits -- confirmed by grep, no test imports `map.json`/`tileset.png`).

```python
def shade_wall(tile):
    """Synthesized highlight/shadow coping band so the flat Room_Builder
    wall block reads as a wall with height. Unchanged from the original
    script -- see its docstring for why this is synthesized rather than
    found (no 32x32 pre-shaded wall set exists in the pack)."""
    shaded = tile.copy()
    px = shaded.load()
    w, h = shaded.size
    top_band, bottom_band = 7, 5
    for y in range(h):
        if y < top_band:
            factor = 1.18
        elif y >= h - bottom_band:
            factor = 0.72
        else:
            continue
        for x in range(w):
            r, g, b, a = px[x, y]
            if a == 0:
                continue
            px[x, y] = (min(255, int(r * factor)), min(255, int(g * factor)), min(255, int(b * factor)), a)
    return shaded
```
